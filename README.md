# Control Bridge

Personal research project: run **Control (2019)** hidden next to **CONTROL Resonant** and play Jesse Faden's
own character and moveset inside Resonant's Manhattan. The architecture follows
[ArkWeb](https://github.com/luki-1/ArkWeb) and [SkyCraft](https://github.com/chasmlol/SkyCraft):
- the hidden *guest* (Control) drives the character
- the *host* (Resonant) shows it, with Dylan as a hidden puppet
- the two talk over shared memory

Single-player, offline, personal use. **No game files or anything extracted from them goes into this
repository** (`.gitignore` keeps logs, dumps, backups and build output out).

**Status: Phase 0 (recon).** Passive probe DLLs are built and self-tested offline, but haven't run in a
game yet. Findings, addresses and the ArkWeb comparison are in [PHASE0.md](PHASE0.md).

## Layout

| Path | What |
|---|---|
| `src/common/probe.h` | Probe core: log, live command file, guarded reads, MinHook wrapper, runtime RTTI lookup, heap scan, XInput/keyboard sampler, per-frame CSV |
| `src/common/wwise.h` | Wwise observer, used in both games: frame tick, listener (camera), emitters, plus the `m::PerspectiveView` camera finder |
| `src/probe_control/` | Control probe, a `winmm.dll` proxy (`fwd_winmm.h` is generated by `tools/gen_forwarders.py`) |
| `src/probe_resonant/` | Resonant probe, a crloader mod |
| `tests/selftest.cpp` | Offline test of the core: RTTI, heap scan, hooks with pass-through, transform decoding, commands, CSV |
| `tools/` | Read-only static analysis (pefile + capstone): `pe_survey.py`, `rtti_ns.py`, `dump_exports.py`, `disexp.py`, `check_probe_targets.py` |
| `third_party/minhook` | MinHook (BSD-2), vendored source |

## Build

`build.bat` needs Visual Studio 2019+ with the x64 C++ tools. It finds Visual Studio through vswhere and
builds at low priority on one core. Then run `bin\selftest.exe`; it must print `SELFTEST OK`.

To check that the hook targets exist in your installed builds (read-only):
`python -I tools\check_probe_targets.py "<Control folder>" "<Resonant folder>"`

## Install / uninstall (both games closed)

```
powershell -ExecutionPolicy Bypass -File install_probes.ps1 [-Game control|resonant|both]
powershell -ExecutionPolicy Bypass -File uninstall_probes.ps1
```

Install backs up both games' Steam saves to `backups\<time>\` first. It then copies:
- `winmm.dll` + `controlbridge.ini` next to `Control_DX12.exe`
- `cb_probe_resonant.dll` + `controlbridge.ini` into `CONTROL Resonant\crmods\ControlBridgeProbe\`

It refuses to overwrite a file it didn't install (for example another mod's `winmm.dll`). It records
hashes in `install_manifest.json`, and uninstall removes exactly those files. Game paths are parameters
(`-ControlDir`, `-ResonantDir`).

`controlbridge.ini` keys (section `[ControlBridge]`):
- `LogDir`
- `FrameCsv` (0/1), `FrameCsvEvery` (write every Nth frame), `FrameCsvMinutes` (per file)
- `CallGetTransform` (Control, default 1; 0 stops the probe from calling `EntityState::getTransform`)

## What the probes record

All output goes to `logs\`, set by `LogDir=` in `controlbridge.ini`:

- `<game>_probe.log`: hook results, then every 5 s a summary: pad, Wwise call rates, listener,
  nearest emitters, and in Control also Jesse's transform and the live cameras.
- `<game>_frames_<time>.csv`: one row per frame (Wwise `RenderAudio`), 20 min per file by default.

| Columns | Meaning |
|---|---|
| `t, frame, tid, flags` | Seconds since start, frame number, thread. Flags: 1 player, 2 camera, 4 listener, 8 emitter, 16 no frame tick (20 Hz fallback) |
| `p0..p15` | Control: Jesse's `EntityState::getTransform` matrix, raw floats |
| `c0..c11, fov` | Control: auto-picked camera's view-to-world (doubles) and FOV. Resonant: the view chosen with `view` |
| `lis_*` | Wwise default listener: position, front, top |
| `emi_*` | Tracked emitter (default: nearest to the listener) |
| `pad..ry, keys, fg` | XInput pad (system `xinput1_4`, unaffected by other mods' hooks), keys W A S D Space LShift LCtrl E Q F R Tab LMB RMB MMB C V G as bits 0..17, game window in front |

## Live commands

Write lines into `logs\control_cmd.txt` or `logs\resonant_cmd.txt`. The probe runs them within 250 ms,
logs the results and deletes the file.

| Commands | |
|---|---|
| Both | `help`, `mem <addr> [size]`, `ptr <addr>`, `bin <addr> <size> <name>`, `mod <dll>`, `rtti <addr>`, `vt <Class@ns> [max] [dll]`, `csv on\|off\|new`, `frames` |
| Wwise / views | `emitters [n]`, `track <id>\|auto\|off`, `views [max]`, `view <addr>\|off [matOff] [fovOff]` |
| Control | `avatar`, `cams`, `cam <i>\|auto` |

Addresses can be hex, `exe+rva` or `module.dll+rva`.

## Safety notes

- The probes only observe: every hook calls the original unchanged, and nothing in either game is
  written.
- `vt` and `views` scan the heap. Run them while standing still, not during combat.
- Resonant autosaves. Back up its save before every session (install does this).
- Pin game versions once something works: everything after Phase 0 will depend on build-specific
  details.
